# 截图 / 照片识别（OCR + 自动填表）供应商参考

> 用途：Enquiry「Share / 截图建线索」、Leads 多张截图、DK 拍照。输入多是门户询盘截图（realestate.com.au / Domain 邮件）、微信/短信聊天截图、名片、手写便条；输出是表单字段（姓名、手机、邮箱、地址、询盘类型、需求备注）。
> 价格为 2026 年公开价目的量级估算，签约前以官网报价为准。

## 1. 关键结论
- **纯 OCR 只能出文字，不能直接填表。** 截图里“谁是客户、哪个是手机号、要买还是要卖”需要理解上下文，所以要么 OCR + 大模型结构化，要么直接用带视觉能力的大模型。
- **个人信息要留在澳洲区域、且不被用于训练**（与 Rex 数据同一标准）。优先选能在悉尼/墨尔本区域调用的服务。
- 量级很小：按每位中介每天 10 张、10 位中介估算，每月约 3,000 张，任何方案每月费用都在几十澳元以内，**选型看准确率和合规，不看价格**。

## 2. 方案对比

| 方案 | 代表产品 | 中文/截图效果 | 能否直接出字段 | 澳洲区域 | 费用量级 | 备注 |
|---|---|---|---|---|---|---|
| A. 手机端 OCR（离线） | Apple Vision（iOS 自带）、Google ML Kit Text Recognition v2 | 英文好；中文简体可用，繁体/手写一般 | 否，只出文字 | 不出手机，最合规 | 免费 | 需要原生模块（Expo dev build 已具备条件）；可做“先在手机上识别，再把文字发后端结构化”，图片本身不上传 |
| B. 云 OCR | AWS Textract、Azure AI Document Intelligence（Read / Layout）、Google Cloud Vision | 英文印刷体很好；中文 Azure、Google 较好，Textract 中文支持有限 | 部分（键值对/表格），聊天截图基本不行 | AWS 悉尼、Azure Australia East 有；Google 需确认具体产品的区域 | 约 1.5 美元 / 千页 | 适合名片、表格类；对聊天截图需要再接大模型 |
| C. 视觉大模型（推荐） | Claude（AWS Bedrock 悉尼区域）、GPT-4.1 / GPT-4o（Azure OpenAI Australia East）、Gemini（Google Vertex AI，区域需确认） | 截图、聊天记录、中英混排、手写都明显好于传统 OCR | **是**，按我们给的 JSON 字段直接输出，并给出置信度 | Bedrock 悉尼 / Azure 澳东可选，企业条款默认不用于训练 | 约 0.5–2 美分 / 张 | 一次调用完成识别+填表；多张截图可以一起发，模型自行合并去重 |
| D. 自建开源 | PaddleOCR（中文强）、Tesseract | PaddleOCR 中文好；Tesseract 对截图一般 | 否 | 部署在我们自己的澳洲服务器 | 只有服务器成本 | 需要 GPU 或较强 CPU，维护成本高，不建议第一阶段 |

## 3. 建议
1. **第一阶段：方案 C**，首选 **Claude on AWS Bedrock（悉尼 ap-southeast-2）**，备选 **Azure OpenAI（Australia East）**。后端统一一个 `/captures/ocr` 接口，供应商做成可切换配置。
2. 流程：手机压缩图片（长边 1600px）→ 后端 → 视觉大模型，按固定 JSON Schema 输出字段 + 每个字段的置信度与原文片段 → App 预填表单，低置信度字段标黄让中介确认 → 保存。**原图默认不在服务器保留**（处理完即删，只留审计记录）。
3. **可选增强（方案 A + C）**：iOS/Android 先在手机上做 OCR，只把文字发给大模型，图片不出手机，合规最好；代价是聊天气泡归属、版面信息会丢一部分，准确率略降。可在试点后按中介意见决定。
4. 需要业务方确认：是否接受“图片发到澳洲区域的云端大模型处理，不保留、不训练”；若不接受，走方案 A + 规则提取，准确率会明显下降。

## 4. 试点验证方法
- 收集 30–50 张真实截图（门户邮件、微信、短信、名片各若干，打码后可用），两个候选供应商各跑一遍。
- 指标：手机号/邮箱完全正确率、姓名正确率、询盘类型正确率、平均耗时、每张费用。
- 预计 1–2 天出结果，再定供应商。
