# AxleoCollect API (B4)

The Vue admin console is built in `../web/` (`NODE_ENV=development npm ci --include=dev && npm run build`) with Vite base `/admin/`. The lazily fetched `web/public/parcels.json` is a copy of `mobile/src/data/sunnybank.json`: QLD Spatial LandParcelPropertyFramework addresses and cadastral rings, © State of Queensland, CC BY 4.0. It contains public geometry, not licensed ownership. When the source changes, sync it from the repository root with `cp mobile/src/data/sunnybank.json web/public/parcels.json`, then rebuild and commit the static asset. The browser joins decoded micro-degree rings to admin-only parcel statuses by lot/plan; no owner data is present in the static file. **Generated `server/web/` assets are committed**, so a clean checkout runs `go test ./...` and `go build` without Node. Rebuild and commit the generated files whenever changing `web/src/`; the old vanilla admin page has been replaced. The embedded server serves `/admin/` with hash-history routes. Vite chunk names carry a `chunk-` prefix because Go's `go:embed` skips files whose basename begins with `_` (one upstream Vue chunk does). No licensed ownership bulk-export endpoint is provided.

Admin-only parcel APIs: `GET /api/v1/admin/properties?q=&suburb=&registered=true|false&hasOwner=true|false&minYearsHeld=<years>&cursor=<id>&limit=1..100` returns at most 100 parcel records per page, including owner names, absentee flag and covering agents. `GET /api/v1/admin/properties?bbox=<west>,<south>,<east>,<north>&limit=1..100` returns at most 5000 GeoJSON features with null geometry and only `id`, `lotplan`, `registered`, `hasOwner` status properties (never owner names). The client joins lotplan to public QLD cadastral rings; bbox must be at most one degree in each direction. `GET /api/v1/admin/parcel-stats` returns parcel, registration and ownership totals by suburb. `GET /api/v1/admin/zones` lists active zones; `POST /api/v1/admin/zones` accepts `{ownerId,name,pts:[[lat,lng],...]}` or `{ownerId,name,center:[lat,lng],radius:<metres>}` or `{ownerId,name,suburbs:[...]}`; `PATCH /api/v1/admin/zones/{id}` additionally requires `version`, and `DELETE /api/v1/admin/zones/{id}` soft-deletes. Writes use generic resource mutation, with sync triggers and audit records.

Phase 2 admin work queues (all admin-only; agent tokens return 403): `GET /admin/market-review`, `GET /admin/market-review/{id}/candidates`, `POST /admin/market-review/{id}/link` with `{propertyId}` or `/ignore` with `{}`. Migration `009_market_review.sql` adds a review status to unmatched market events. `GET /admin/captures` lists outstanding voice captures with their agent. `GET /admin/todos?assignee=&from=&to=&done=`, `POST /admin/todos` (assigneeId, d, t required), `PATCH /admin/todos/{id}` (version required) use the generic resource mutation path. `GET /admin/listings`, `/admin/ofi_attendees`, and `/admin/contacts?q=` serve the OFI list and searchable contacts; `PATCH /admin/ofi_attendees/{id}` (version required) records follow-up state through the same mutation path. Admin endpoints in this paragraph are relative to `/api/v1`. The local seed contains OFI events and attendees for development; it does not modify production data.

Go 1.27, SQLite (pure Go), standard-library HTTP server. From `server/`:

`axleo rex-probe --account <sandbox-id> [--write]` verifies the Rex sandbox; see `../docs/rex-sandbox-probe.md`.

Market data is licensed to the agency (not supplied by Rex). Never export or redistribute provider records; the admin UI offers no bulk export. Pricefinder XLS (BIFF8), XLSX and CSV (UTF-8/BOM) imports are supported (20 MB maximum). Snapshot imports update matched ownership, record dated sales and only notify covering agents for newer sales within 90 days. Owner addresses and vendor/purchaser names are never persisted; absenteeOwner is visible only to covering agents and admins. See `../docs/market-data.md` for aliases, privacy, API authorization and import instructions. `axleo market-import <file> [--provider pricefinder] [--kind auto|sale|listing|ownership] [--dry-run]`; admin-only `POST /api/v1/admin/market/imports` (multipart `file`, `kind`, `provider`, `dryRun`; 20 MB), `GET /api/v1/admin/market/imports`, `GET /api/v1/admin/market/imports/{id}`. `axleo market-pull` is a no-op until an authorized API contract/documentation is supplied; the optional deploy timer is disabled by default.

Rex outbox writes are off by default. Set all of `REX_BASE_URL`, `REX_APP_ID`, `REX_EMAIL`, `REX_PASSWORD`, and an explicit `REX_ACCOUNT_ID` (2057 shared sandbox, 758 Place Sunnybank production). Missing any means no Rex calls. `AXLEO_REX_READ=1` enables future read integrations; `AXLEO_REX_WRITE=1` **and** `REX_WRITE_ACCOUNT_ID` exactly matching `REX_ACCOUNT_ID` starts the worker. The old `AXLEO_REX_ENABLED` is ignored (startup warning). Configure these in `/etc/axleo/env`. `rex-probe --account` must match the configured account; probe writes additionally require `--write`. Every HTTP attempt and webhook delivery is logged (redacted) in `rex_request_log`, retained 180 days with cleanup on service startup. Admin-only `/api/v1/admin/rex/status`, `/api/v1/admin/rex/log`, `/api/v1/admin/rex/log/{id}` expose status and logs. `REX_INTERVAL_MS` sets the minimum interval between Rex requests (default 1000 ms; values below 1000 are ignored). Set `users.rex_user_id` to assign leads/reminders to agents. Admins can retry failed/skipped rows using `POST /api/v1/admin/rex-outbox/{id}/retry`. **Before retrying an uncertain create failure, reconcile the record in Rex and populate `rex_links` manually**: Rex has no idempotency key, so an unknown write outcome cannot be replayed safely. Property-only reminders require a pre-existing `rex_links` property mapping. Keep credentials in the protected deploy environment, never in the database or logs.

`AXLEO_ADDR` defaults to `127.0.0.1:8082`; `AXLEO_DB` to `./axleo.db`; migration snapshots use `AXLEO_BACKUP_DIR` (default `backup/` beside the DB). `axleo passwd <email>` reads the replacement password from stdin and revokes existing sessions. Without `AXLEO_SEED_PASSWORD`, the first seed prints a generated password **once**; save it. `seed` is repeatable and does not overwrite existing accounts or records.

All protected endpoints use `Authorization: Bearer <token>`; `/api/v1/health` is public. Collections return JSON arrays; PATCH requires `version`, with stale updates returning `409` and `current`. `GET /sync?since=<opaque cursor>` returns `cursor`, `full`, registered contacts/properties/todos and B3 resources, plus `deleted` ID arrays, all scoped to the bearer. An empty cursor requests a full snapshot. `POST /sync/push` accepts `ops` with `opId`, `kind`, `op`, `id`, optional `baseVersion`, and `data`; `results` contain per-op `status` and `record`. Op IDs are idempotent per user for seven days. `GET /team` returns same-team user IDs and names. API supports cross-origin bearer requests. Admin-only endpoints are under `/api/v1/admin/`.

B3 CRUD kinds: `captures`, `enquiries`, `leads`, `listings`, `ofi_attendees`, `sales`, `contracts`, `referrals`, `market_items`, `zones`, `tags`. `listings` are readable by every agent but only the listing owner/admin can PATCH or DELETE; non-owner writes return **404**. OFI attendee personal data is returned separately from globally visible listings. `GET /approvals` lists own requests (admin: all); `POST /approvals` accepts `{kind:"merge",primaryId,secondaryId}` or `{kind:"reassign",entity:"contacts"|"todos",id,targetId}`. Admin can `POST /approvals/{id}/decide` with `{decision:"approve"|"reject",note}`. Admin direct actions: `POST /contacts/{id}/merge` with `{secondaryId}` and `POST /contacts/{id}/reassign` or `/todos/{id}/reassign` with `{targetId}`. Unauthorized records and agent decisions return 404.

Regenerate embedded demo data at repository root with `node tools/export-seed-json.mjs`. Demo `Owen Chen` is assigned to Mary; `Natalie Wong` to John. Original `owner`/`who`/`by` display strings are preserved.

Speech/extraction endpoints (Bearer auth): `POST /api/v1/stt/transcribe` accepts multipart `audio` (WAV, m4a, mp3, webm; max 10 MB total) and `lang` (`en`, `zh`, `yue`; default `zh`); WAV duration is limited to 120 seconds. Returns `{text,lang,durationMs,latencyMs}`. `POST /api/v1/ai/extract` accepts JSON `{text,ctx?,lang?}` (text ≤ 4000 Unicode characters; ctx `dk`, `oh`, `enq`, `note`) and returns `{fields,confidence,model,latencyMs}`. Fields include `contactName`, `firstName`, `lastName`, `phone`, `email`, `address`, `suburb`, `intent`, `priceMin`, `priceMax`, `timeframe`, `notes`, `language`. Both share a per-user limit of 30 calls/minute; audit records only metadata, never text/audio. Unknown extracted values are null; do not write to Rex without human confirmation. Set `AXLEO_AZURE_SPEECH_KEY` (required), `AXLEO_AZURE_SPEECH_REGION` (default `australiaeast`), `AXLEO_BEDROCK_API_KEY` (required), `AXLEO_BEDROCK_REGION` (default `ap-southeast-2`), `AXLEO_BEDROCK_MODEL` (default `au.anthropic.claude-haiku-4-5-20251001-v1:0`; **must start with `au.`**). Missing credentials return 503. `POST /api/v1/tts` accepts JSON `{text,lang}` (1–500 trimmed Unicode characters; `en`, `zh`, `yue`) and returns `audio/mpeg` MP3 bytes using Azure Speech; its per-user limit is 60/minute, separate from STT. `POST /api/v1/ai/translate` accepts JSON `{text,from,to}` (1–1000 trimmed Unicode characters; languages `en`, `zh`, `yue`) and returns `{text,from,to,model,latencyMs}`. Matching source/target languages return the text without an upstream call; its per-user limit is 30/minute, separate from extraction. Both require Bearer auth and audit metadata only (language, character count, timing/status or token counts), never text or audio. They reuse the Azure Speech and Bedrock environment variables above; the Bedrock model must start with `au.`. See `deploy/env.example`; never commit real keys.

Deployment templates are in `deploy/`: run `setup-65.sh` on the target as root **after review**, set `/etc/axleo/env`, then run `release.sh` locally with Go and `SSHPASS` set. The scripts are provided but are not run automatically. Daily systemd timer calls `axleo backup /data/axleo/backup` (SQLite online snapshot) and retains 14 snapshots. `axleo verify <file>` checks integrity/schema and prints table counts; `axleo restore <file>` requires the service stopped and saves a copy of the existing database first. `/admin/` serves the embedded administration UI; admin-only JSON endpoints include `/admin/overview`, `/admin/approvals?status=`, `/admin/data?kind=&before=`, plus filtered `/admin/audit` and `/admin/rex-outbox`. See `docs/ops-runbook.md` for operating instructions. Do not expose the service directly to the Internet without TLS/reverse proxy.
